# ФинКом

**Финансовый компас для студента: прогноз бюджета до следующего поступления.**

Сервис отвечает не на вопрос «сколько я потратил», а на вопрос «можно ли мне купить это сегодня».
Он строит прогноз остатка по дням на 30 дней вперёд и называет **самую раннюю дату, с которой
покупка не выведет за границы бюджета**.

Кейс 1 Т-Банка «AI в личных финансах», стартап-хакатон «Пятый элемент» (СФУ), 26–27 сентября 2026.

> **Все суммы, даты и остатки считает обычный код** — модуль `backend/app/engine`.
> AI понимает вопрос на естественном языке и пересказывает готовый расчёт. Числа он не придумывает:
> если в ответе появляется число, которого нет в расчёте, ответ отбрасывается и подставляется шаблон.

---

## Где посмотреть

Сейчас сервис запускается локально — инструкция ниже, всё поднимается двумя командами и работает
без интернета и без ключей. Публичный адрес появится, когда поднимем VDS: трафик будем проксировать
на ту же пару «API + статика».

| | |
|---|---|
| Интерфейс | http://localhost:5173 |
| API | http://localhost:8000 |
| Документация API (Swagger) | http://localhost:8000/docs |
| Живая самопроверка расчётов | http://localhost:5173 → «Как мы проверяли» |

## Для кого и какая проблема

**Сегмент:** студенты 18–22 лет в первый год самостоятельной жизни — общежитие, стипендия, деньги
от родителей, иногда нерегулярная подработка.

**Проблема:** деньги приходят редко и крупными порциями, а уходят каждый день понемногу. Человек
не понимает, доживёт ли до следующего поступления, и особенно — можно ли сейчас потратиться на
что-то заметное. Учёт по категориям при этом почти никто не ведёт: в нашем опросе 10 из 18 ответили,
что смешивают все деньги в общем бюджете.

**Что делает сервис:** спрашивает пять вещей (сколько на карте, когда придут деньги, обязательные
платежи, сколько уходит в день, цель) и сразу даёт прогноз по дням, проверку покупки и план
действий. Вести учёт месяцами не нужно.

## Что уже работает

**1. Прогноз до следующего поступления.**
Остаток по дням на 30 дней. Состояние подписано словами: «Бюджета хватает до следующего поступления
средств», «Может не хватить», «Зависит от подработки». Под прогнозом всегда стоит оговорка, что это
прогноз, а не гарантия.

**2. Проверка покупки — главная функция.**
«Наушники за 3 000 ₽ сегодня» → дата исчерпания средств, максимальное превышение бюджета, **дата,
с которой покупку можно сделать без превышения**, и насколько сдвинется накопительная цель.
Ответ не «да/нет», а дата, с которой можно действовать.

**3. Разделение денег на надёжные и ненадёжные.**
Обязательные платежи и подтверждённый доход идут в прогноз на точную дату. Неподтверждённые
поступления (подработка, разовый перевод) считаются отдельно: график показывает **два сценария
одновременно** — сплошной линией без подработки, пунктиром с ней, а между ними заливку «разница
сценариев». Если весь прогноз держится на неподтверждённом доходе, сервис говорит об этом прямо,
а не пишет «денег хватает».

**4. План, как остаться в границах бюджета.**
Три варианта с честной пометкой «легко» или «сложно»: перенести покупку на конкретную дату,
сократить расходы на N ₽ в день, найти N ₽ к дате. Если вариант не сработает даже теоретически —
так и написано.

**5. Чат на естественном языке.**
«А ноут за 35к потяну?», «дотяну ли до стипы», «сегодня такси 800» — своя модель определяет одно из
12 намерений и вызывает нужную функцию движка. Работает офлайн, 30 МБ, без внешних ключей.

**6. «Как посчитали?».**
Панель с формулой, всеми исходными данными и списком «Чего мы не знаем». Любую цифру можно
поменять прямо там и сразу увидеть пересчёт.

**7. Объяснение терминов со ссылкой на источник.**
9 терминов (финансовая подушка, кассовый разрыв, ликвидность, рассрочка, льготный период и другие).
Каждый — со ссылкой на конкретную статью fincult.info, сайта Банка России. Ссылки проверяются
скриптом `training/check_prod_terms.py`.

**8. Обучающая карточка и примеры подработки.**
«Как устроены накопления и инвестиции»: подушка → цель → инвестиции, и отдельно про Т-Инвестиции
как следующий шаг. Текст одинаковый для всех, суммы пользователя в нём не используются, и при
превышении бюджета карточка не показывается. Рядом — окно «Где искать подработку» с тремя учебными
примерами (помечены «Пример»), реальными площадками для поиска и предупреждением про мошенников.

**9. Живая самопроверка.**
Страница «Как мы проверяли»: сервер прямо во время демонстрации прогоняет 13 эталонных сценариев и
показывает «ожидали / получили / ✓». Значения посчитаны командой вручную заранее.

## Чего сервис не делает — намеренно

- **Не даёт инвестиционных советов.** На «куда вложить 5 000?» вежливо отказывает, суммы
  пользователя для таких ответов не использует и предлагает разобраться в терминах.
- **Не совершает операций с деньгами** и не принимает решений за пользователя. Везде написано
  «решение за вами».
- **Никогда не спрашивает** пароли, коды из СМС, CVV и номер карты. На такую просьбу отвечает
  предупреждением о мошенниках.
- **Не выдаёт предположение за факт.** У каждой суммы метка: факт, ожидается, может не прийти,
  оценка.
- **Не придумывает числа.** Модель видит только готовые строки расчёта; ответ с посторонним числом
  отбрасывается автоматически.

## Как запустить локально

Нужны Python 3.11 и Node.js 20. Docker не нужен, интернет и API-ключи не нужны.

**Windows (PowerShell)**

```powershell
# backend — первый терминал
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --reload --port 8000

# frontend — второй терминал
cd frontend
npm install
npm run dev
```

**macOS / Linux (bash)**

```bash
# backend — первый терминал
cd backend
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --port 8000

# frontend — второй терминал
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Запросы `/api` фронтенд сам проксирует на `localhost:8000`
(настройка в `frontend/vite.config.ts`), поэтому `VITE_API_URL` локально оставляем пустым.

**Тесты:** `cd backend` и `pytest` — 275 проверок, включая 13 эталонных сценариев из
[docs/checks.md](docs/checks.md).
**Проверка типов и сборка фронта:** `cd frontend`, затем `npx tsc -b` и `npm run build`.
**Проверка API целиком** (13 эталонов + 18 краевых случаев): при запущенном бэкенде
`cd backend` и `python -m scripts.final_check --base http://127.0.0.1:8000`.

### Публикация за реверс-прокси (VDS)

`frontend/.env.production` оставлен пустым намеренно: собранный фронтенд ходит в API по тому же
адресу, с которого отдан, — `/api/...`. Достаточно поставить перед ними любой реверс-прокси:

```nginx
location /      { root /var/www/fincom; try_files $uri /index.html; }
location /api/  { proxy_pass http://127.0.0.1:8000; }
```

Если API вынесен на отдельный домен, задайте `VITE_API_URL` при сборке фронтенда и добавьте этот
домен в `CORS_ORIGINS` бэкенда.

## Переменные окружения

`backend/.env`, в git лежит только `.env.example` — реальных ключей в репозитории нет.

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `NLU_MODE` | `sklearn` | чем понимаем вопрос: `onnx` / `sklearn` / `rules` |
| `NLU_MIN_CONFIDENCE` | `0.6` | ниже этой уверенности переходим на правила или переспрашиваем |
| `EXPLAIN_MODE` | `templates` | чем пишем пояснение: `templates` / `local` / `yandex` / `anthropic` |
| `LLM_MODEL_PATH` | пусто | папка своей генеративной модели для `EXPLAIN_MODE=local` |
| `DEMO_TODAY` | `2026-09-27` | «сегодня» для демонстрации |
| `CORS_ORIGINS` | `http://localhost:5173` | с каких адресов фронтенд может обращаться к API |

Рабочая конфигурация демонстрации — `NLU_MODE=onnx`, `EXPLAIN_MODE=templates`: всё считается
локально, без интернета и без ключей.

## Пример входных данных

Все данные синтетические. Демо-персоны — в
[backend/app/data/personas.json](backend/app/data/personas.json). Ситуация студентки Ани
(сокращено: без истории операций и категорий трат):

```json
{
  "today": "2026-09-27",
  "balance": 6900,
  "daily": 300,
  "incomes": [
    { "id": "i1", "name": "Стипендия", "amount": 3200, "date": "2026-10-10", "confirmed": true },
    { "id": "i2", "name": "Перевод от родителей", "amount": 10000, "date": "2026-10-15", "confirmed": true }
  ],
  "obligations": [
    { "id": "o1", "name": "Подписка на музыку", "amount": 200, "date": "2026-10-01" },
    { "id": "o2", "name": "Связь", "amount": 400, "date": "2026-10-03" },
    { "id": "o3", "name": "Общежитие", "amount": 1800, "date": "2026-10-05" }
  ],
  "spends": [],
  "goal": { "name": "Ноутбук", "target": 40000, "current": 25000, "date": "2027-06-01" }
}
```

- `balance` — факт: сколько денег сейчас.
- `daily` — оценка: обычные траты в день.
- `incomes` — поступления. `confirmed: true` — основной доход, придёт вовремя; `false` —
  дополнительный, может не прийти, и тогда прогноз строится в двух вариантах.
- `obligations` — обязательные платежи на дату; `spends` — разовые траты.
- Суммы — целые рубли, даты — `YYYY-MM-DD`.

**Что получится:** без покупок минимум **600 ₽ к 9 октября**. Наушники за 3 000 ₽ сегодня выводят
за границы бюджета с 5 октября (превышение до 2 400 ₽), а **без превышения их можно купить
с 15 октября**; накопительная цель сдвигается на 50 дней.

Проверить через API:

```bash
curl -s http://127.0.0.1:8000/api/personas/anya
curl -s -X POST http://127.0.0.1:8000/api/purchase/check \
  -H "Content-Type: application/json" \
  -d '{"situation": <situation из ответа выше>, "purchase": {"amount": 3000, "date": "2026-09-27", "name": "Наушники"}}'
```

## Как устроено

```
браузер → FastAPI → движок (чистые функции Python)
                  → своя модель намерений (ONNX) → выбор функции движка
                  → шаблоны ответов → guard (проверка чисел)
```

| Слой | Где | Что делает |
|---|---|---|
| Движок | `backend/app/engine` | все расчёты: прогноз по дням, покупка, план, цель, валидация |
| API | `backend/app/api` | схемы строго по [docs/CONTRACT.md](docs/CONTRACT.md), раздел 6 |
| Понимание вопроса | `backend/app/ai/nlu` | 12 намерений: rubert-tiny2 → ONNX int8, запасные TF-IDF и правила |
| Ответы | `backend/app/ai/templates.py`, `tools.py` | шаблоны + вызовы функций движка |
| Проверка чисел | `backend/app/ai/guard.py` | отбрасывает ответ с числом, которого нет в расчёте |
| Интерфейс | `frontend/src` | React 18 + TypeScript + Vite, график — свой SVG без библиотек |
| Обучение моделей | `training/` | датасеты, обучение, метрики, отчёты |

**Сервер без состояния:** ситуация студента живёт в браузере и приходит с каждым запросом.
Базы, регистрации и хранения нет — утекать нечему.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | какой режим модели и пояснений включён |
| GET | `/api/personas`, `/api/personas/{id}` | демо-персоны Аня и Даня |
| POST | `/api/validate` | проверка анкеты с ошибками по конкретным полям |
| POST | `/api/dashboard` | всё для главного экрана одним запросом |
| POST | `/api/purchase/check` | «когда можно купить» и план действий |
| POST | `/api/chat` | чат: модель понимает вопрос, движок считает |
| GET | `/api/checks` | 13 эталонных проверок вживую |

## Свои модели

**Модель 1 — классификатор намерений (работает в сервисе).** Дообученная `rubert-tiny2`,
12 классов, экспорт в ONNX int8. 30 МБ, ответ меньше 2 мс на процессоре, без интернета.
На тесте из формулировок, которых не было в обучении: 336 из 360 (93,3%), macro-F1 0,934.
На 60 живых фразах, которые написали двое участников, не видевшие обучающих данных: **52 из 60**.
Безопасные классы (пароли, переводы, инвестсоветы) — 12 из 12.

**Модель 2 — генеративный пояснитель (обучена, по умолчанию выключена).**
`Vikhr-Qwen-2.5-1.5B-Instruct`, QLoRA, 7 220 примеров, 2 часа на одной RTX 2060 SUPER.
Честность чисел на тесте — 100% в 4 битах против 63% у той же модели без обучения.
Включается флагом `EXPLAIN_MODE=local`, весов в репозитории нет — собираются
`training/train_llm.py` → `training/merge_llm.py`. По умолчанию выключена: демонстрация обязана
работать без видеокарты, а на шаблонах ответы детерминированы.

Подробности и матрицы ошибок — [docs/ai/model_card.md](docs/ai/model_card.md).

## Известные ограничения

- **Прогноз на 30 дней.** Что будет дальше, сервис не показывает и прямо пишет об этом.
- **Обычные траты в день — оценка,** а не факт. Необычные будущие траты (подарки, поломки) прогноз
  не знает.
- **Разбор трат по категориям работает на демо-персонах.** В своей анкете категории и история
  операций не собираются, поэтому на вопрос «куда уходят деньги» сервис честно отвечает, что
  истории трат пока нет.
- **Демо-дата зафиксирована:** «сегодня» = 27 сентября 2026 (`DEMO_TODAY`), чтобы числа совпадали
  с эталонными проверками.
- **Модель понимания вопросов обучена на синтетических фразах.** На живых формулировках ошибается
  примерно в одном случае из семи; при низкой уверенности включаются правила или сервис
  переспрашивает.
- **Данные не сохраняются.** Ни регистрации, ни базы: ситуация живёт в браузере и пропадает после
  закрытия вкладки.
- **Только синтетические данные.** Реальные выписки, счета и карты не подключаются.
- **Десктоп-веб.** На телефоне открывается и не ломается, но отдельной мобильной вёрстки нет.
- **Публичного адреса пока нет** — сервис поднимается локально, VDS в работе.
