# Что нужно от A и D, чтобы AI-слой работал на проде

Роль B не пишет в `backend/requirements.txt` и `render.yaml` — это чужие файлы. Ниже ровно то,
что нужно поменять, чтобы `/api/chat` заработал на Render.

## 1. `backend/requirements.txt` (владелец A) — обязательно

Контракт, раздел 3, прямо предусматривает это дополнение от B. Добавить:

```
scikit-learn
joblib
numpy
onnxruntime
tokenizers
```

**Без этих строк на проде не загрузится ни sklearn-модель, ни ONNX**: слой честно уйдёт в режим
правил (13 из 13 контрольных фраз пройдут, но «модель: purchase_check · 94%» в чате не появится,
а это как раз то, что мы показываем жюри).

`torch` и `transformers` в этот файл добавлять **нельзя** — они только в
`training/requirements-train.txt`.

## 2. Переменные окружения на Render (владелец D)

Берутся из `backend/.env.example`:

```
NLU_MODE=sklearn              # решение по onnx принимаем в 23:00, см. ниже
NLU_MIN_CONFIDENCE=0.6
EXPLAIN_MODE=templates
DEMO_TODAY=2026-09-27
CORS_ORIGINS=https://<домен фронта>
```

Ключей API не нужно: демо работает без интернета.

## 3. Решение «onnx или sklearn» — ФИНАЛ: `NLU_MODE=onnx`

Три условия плана B.4 и их состояние:

| Условие | Статус |
|---|---|
| macro-F1 на holdout_team не хуже sklearn | да: обе модели 20 из 20 на фразах A (ничья 1,00) |
| Render стартует без ошибок по памяти (512 МБ) | да: локально RSS 204 МБ с ONNX против 131 МБ с sklearn |
| `/api/chat` быстрее 300 мс | да: медиана 0,9 мс (ONNX) и 1,1 мс (sklearn) на 10 фразах |

Все три условия выполнены, и на test нейросеть заметно лучше: macro-F1 0,934 против 0,915.
**Решение принято и оно финальное: в проде `NLU_MODE=onnx`.** В `render.yaml` это выставлено
в ветке `b/prod-ml-deps` (PR ждёт ревью A и D).

Оговорка, которая остаётся: holdout сейчас — только 20 фраз от A, D свои 40 ещё не прислал.
На таком объёме ничья 20/20 не различает модели. Когда фразы D придут, пересчитываем
`python eval.py --holdout --onnx` и обновляем model card. Если нейросеть внезапно окажется хуже —
меняем одну переменную окружения на Render обратно на `sklearn`, передеплой не нужен.
`GET /api/health` всегда показывает, что реально включено.

### Чем это проверено на проде

`GET https://dotyanu-api.onrender.com/api/health` сейчас отвечает `{"ok":true,"nlu":"rules",...}` —
то есть **на проде модель не загружена**: в `requirements.txt` ещё нет `scikit-learn` и
`onnxruntime`. `POST /api/chat` при этом работает и отдаёт верные числа (минус с 5 октября,
2 400 ₽, безопасно с 15 октября) — правила справляются, но «модель: purchase_check · 94%»
в чате не появится, пока не пройдёт PR `b/prod-ml-deps`.

Запасной путь есть в любом случае: если модель не загрузится, слой сам уходит в правила
(13 из 13 контрольных фраз), сервер при этом не падает.

## 5. Генеративный пояснитель — ФИНАЛ: выключен на проде

**Решение зафиксировано: на проде `EXPLAIN_MODE=templates`. Вторая модель в прод не идёт.**

Почему так, а не иначе:

- на Render бесплатного тарифа нет ни видеокарты, ни памяти под 3 ГБ весов, ни torch
  в `requirements.txt` — и добавлять его туда мы не будем: это ломает и деплой, и время старта;
- демо обязано работать без интернета, ключей и видеокарты (раздел 9 контракта);
- ответы шаблонами детерминированы: на защите одинаковый вопрос даёт одинаковый текст.

Модель остаётся **локальной возможностью** — показать её можно на ноутбуке с видеокартой:

```
EXPLAIN_MODE=local                                   # включает модель, по умолчанию templates
LLM_MODEL_PATH=...\training\runs\dotyanu_llm_merged  # слитая модель из merge_llm.py
LLM_LOAD_4BIT=1                                      # 4 бита: 1,44 ГБ вместо 2,92 ГБ
```

Включает модель именно `EXPLAIN_MODE=local`; `LLM_LOAD_4BIT=1` только выбирает экономный режим
для слабой видеокарты. Без первой переменной вторая ничего не делает.

Предохранители, из-за которых это ничего не ломает: нет весов, нет torch, не уложилась в
`LLM_TIMEOUT_S` или упала — `local_llm.generate` возвращает `None`, и чат отвечает шаблоном.
Отказы, инвестиции, термины и переспросы модель не пишет никогда (`TEMPLATE_ONLY_INTENTS`).

Проверено на живом проде 26.09 в 23:33: `/api/health` отдаёт `{"nlu":"onnx","explain":"templates"}`.

## 6. Термины и ссылки на источники

`training/check_prod_terms.py` спрашивает прод про каждый термин из `knowledge.json` и проверяет,
что ответ распознан как `term`, ссылка ведёт на конкретную статью fincult.info (не на главную)
и открывается.

```powershell
cd training; python check_prod_terms.py                      # по живому проду
python check_prod_terms.py --url http://localhost:8000       # по локальному
```

Прогон 26.09 в 23:35 на проде: **8 из 8** — все ссылки живые и ведут на статьи.

Одно замечание к содержанию (владелец — D, не правил): «Кассовый разрыв» ссылается на статью
**про факторинг**. Ссылка рабочая, но статья о финансировании бизнеса, а не о том, когда у
студента деньги кончились раньше поступления. Если у D будет время — стоит подобрать другую.
